网络原理

不同于电信网络面向连接的通信方式，网络层向上只提供简单灵活的、无连接的、尽最大努力交付的数据报服务。

也就是说网络层不提供服务质量的承诺。

1. 网际协议: IPIPIP协议#

IPIPIP协议是用来使互连起来的**许多计算机网络(网络之间，网际)**能够进行通信的。

1.1 虚拟互连网络#

在市面上有很多种性能不同、不同网络协议的网络，供不同的用户选用。

从一般的概念讲，将网络连接在一起需要一些中间设备。

​ (1) 物理层使用的中间设备叫做转发器(repeater)。

​ (2) 数据链路层使用的中间设备叫做网桥或者桥接器(bridge)。

​ (3) 网络层使用的中间设备叫做路由器(router)。

​ (4) 在网络层以上使用的中间设备叫做网关(gateway)，用网关连接两个不兼容的系统需要在高层进行转换。

网关的使用非常复杂，因此如今使用的很少了。转发器和网桥是在物理层和数据链路层拓展网络，但这只是把一个网络扩大了，并没有产生新的网络。

因此讨论网络互联一般就指用路由器进行网络互连和路由选择。

如果参加互连的计算机网络都是用同一种网际协议IPIPIP​，那么可以忽略这些网络本身客观存在的异构性，而把它们都看成是一个虚拟互连网络相连接的。

IPIPIP协议使得性能各异的网络看上去就像是一个统一的网络。看不到每个网络具体的细节。

1.2.2 子网的划分#

2级IPIPIP利用率非常低，原因就在于被分配了某一级地址以后，该级别的地址的主机号往往用不完。另外2级IPIPIP地址也不够灵活，没办法立刻在一个地区新开一个网络。

于是1985年在原来二级IPIPIP的基础上增加一个子网号字段。使二级IPIPIP地址变为333级IPIPIP地址。主要的做法是把一个网络分割成几个小的子网，但是对外仍然表现出同一个大网络的特性。

IP:={<网络号>,<子网号>,<主机号>}IP :=\{<网络号>,<子网号>,<主机号>\}IP:={<网络号>,<子网号>,<主机号>}

子网划分是建立在分类IPIPIP的基础上。这些子网对外仍然表现为一个大网络，然而当数据报传到大网络后，又会被路由器分开送到不同的子网。实现的方式是使用子网掩码(subnet mask)

在子网划分中，子网号一般不全0全1。

以划分一个BBB类地址为例，假设子网位数是kkk位，那么子网个数为2k−22^k-22k−2个，主机个数为216−k−22^{16-k}-2216−k−2个。总共有(2k−2)∗(216−k−2)=216−2∗(2k+216−k)+4(2^k-2)*(2^{16-k}-2)=2^{16}-2*(2^k+2^{16-k})+4(2k−2)∗(216−k−2)=216−2∗(2k+216−k)+4个可分配地址。比不划分子网要少一些

子网划分提升了IPIPIP分配的灵活性，但是是以减少可以在网络上连接的主机数量为代价的。

CIDRCIDRCIDR编址就没有子网号全为0这样的概念，因此kkk位网络前缀就有2k2^k2k个网络号，232−k−2个主机号2^{32-k}-2个主机号232−k−2个主机号

使用了CIDRCIDRCIDR划分得到大网络以后，可以继续使用CIDRCIDRCIDR进行二级、多级划分。

1.2.3.2 地址聚合#

CIDRCIDRCIDR也可以继续多级划分，就会造成网络号还是非常多，路由器查找、存储非常慢。地址聚合指的是在路由器表中，路由器往往会把一些处于同一个大的CIDRCIDRCIDR网络的并且下一跳都是同一个路由的表项聚合到一起，有效地减少表项。

在路由时，如果有很多表项都能够匹配成功，则选择网络前缀最长的那一个表项。

网络聚合时往往也是寻找IPIPIP​的最长公共网络前缀。而且要注意网络聚合的时候不能有父网络和其子网络的聚合[重叠]。不能引入其他的网络。

1.2.4 IPIPIP地址和物理地址#

物理地址(MACMACMAC)是物理层和数据链路层使用的地址，而IPIPIP​地址是网络层及以上使用的逻辑地址。

但从网络层上看，IPIPIP协议把下层复杂的细节全屏蔽了，只是用单一的、抽象的IPIPIP地址进行通信，这极大简化了互联网的传输过程。

但数据报在数据链路层进行传输时就变成帧(frame)，只能使用物理地址(MACMACMAC)，在跨局域网时会变。

另外在数据报传输时有以下几个特点:

  1. 网络层上只能看到IPIPIP数据报，IPIPIP源地址和目的地址根本不变
  2. 尽管IPIPIP数据报中有IPIPIP源地址，但是路由选择时只看目的地址。
  3. 数据链路层中只能看见MACMACMAC地址，每当从一个主机/路由器转发到另一个主机/路由器时，主机/路由器都要封装帧，把源MACMACMAC和目的MACMACMAC都告诉数据链路层。

要解决的问题有:

  1. 主机/路由器如何根据IPIPIP得到要发送的帧的目的MACMACMAC(ARPARPARP协议)
  2. 路由器/主机如何在只知道最终目的IPIPIP的情况下找到下一跳IPIPIP(路由表路由表路由表)

1.2.4.1 ARPARPARP协议#

地址解析协议ARP(Address Resolution Procotol)ARP(Address \ Resolution \ Procotol)ARP(Address Resolution Procotol)通过IPIPIP地址解析出局域网内的目的MACMACMAC地址，过去还有逆地址解析协议RARP(Reverse Address Resolution Procotol)RARP(Reverse \ Address \ Resolution \ Procotol)RARP(Reverse Address Resolution Procotol)，通过MACMACMAC地址解析出IPIPIP地址。#

ARPARPARP协议在每台主机/路由器中都设立一个ARPARPARP缓冲区，表中存放了IPIPIP地址向MACMACMAC​​地址的映射，以及**生存时间**。

1.2.4.1.1 同一局域网下#

当终端(可以是主机，也可以是路由器)AAA要向同一局域网中的终端BBB发送数据报时，ARPARPARP​协议的基本工作模式是:

  1. A查找自身的ARP缓冲区bufferbufferbuffer，如果A中ARPARPARP缓冲区存在B的IPIPIP表项，则直接根据表映射出BBB的MACMACMAC地址，结束
  2. 如果缓冲区bufferbufferbuffer中没有BBB的IPIPIP表项，则向局域网内所有终端广播ARPARPARP请求分组，内容是我的IP地址是xx.xx.xx.xx, MAC地址是XX−XX−XX−XX我的IP地址是xx.xx.xx.xx,\ MAC地址是XX-XX-XX-XX我的IP地址是xx.xx.xx.xx, MAC地址是XX−XX−XX−XX，请问IP地址为B.IPIP地址为B.IPIP地址为B.IP的终端的MACMACMAC地址是？
  3. 非BBB终端都无视该帧，而BBB主机发现此数据报文是发送给自己的，则收下这个数据报，并且回复给AAA一个ARPARPARP单播的响应分组，内容是我的IPIPIP地址是xx.xx.xx.xx，MACMACMAC是XX-XX-XX-XX
  4. 主机AAA收到BBB的响应分组后，就在自己的缓冲区里更新BBB的IPIPIP到MACMACMAC的映射，并且BBB也知道了AAA的相关信息，因此再发送数据报就很方便了！
1.2.4.1.2 不同局域网下#

实际上，不同局域网中的AAA和BBB通信时，AAA是没办法通过ARPARPARP协议解析出BBB的MACMACMAC地址的，因为没有必要解析的出来，AAA只需要把数据报转发给可以转发数据报的路由器即可。AAA要做的事情应该是根据下一跳的IPIPIP地址解析出该终端的MACMACMAC​地址，这个过程还是在同一个局域网下的。

所以每次跳转的时候重复同一局域网下的过程就能完成不同局域网下的ARPARPARP​协议工作过程。

通过ARPARPARP协议让网络通信时要完成的复杂物理地址的转换变得很透明，只需要主机AAA和BBB的有独立的IPIPIP，就好像AAA和BBB连在同一个网络下。

1.3 网络层的分组转发#

1.4 网际控制报文协议ICMP(Internet Control Message Protocol)ICMP(Internet \ Control \ Message \ Protocol)ICMP(Internet Control Message Protocol)#

ICMPICMPICMP的所有信息都被封装在IPIPIP数据报内，包括ICMPICMPICMP​自身的首部。

ICMPICMPICMP的首部包括类型、代码、校验和，以及额外的4个字节。首部是所有ICMPICMPICMP报文都不变的。

其中ICMPICMPICMP报文的类型主要分**ICMPICMPICMP差错报告报文和ICMPICMPICMP询问报文**。

ICMPICMPICMP的校验和校验的是整一个ICMPICMPICMP报文！不是只有首部！

1.4.1 差错报告报文#

主要有:

  1. 报文不可到达
  2. 超时(TLL=0)
  3. 报文参数有误
  4. 重定向

这几种差错。

对于差错报告报文的数据部分，取的是:出错的IPIPIP数据报的首部[定位该出错IPIPIP数据报]和该IPIPIP数据报数据字段的前8字节[TCPTCPTCP和UDPUDPUDP协议中的端口号]

然鹅，并非所有出差错的IPIPIP数据报都需要发送差错报告报文，

比如:

  1. 对装有ICMPICMPICMP差错报文的IPIPIP数据报不再发送ICMPICMPICMP差错报文
  2. 除了分片的第一个IPIPIP数据报以外，其余所有后续的数据报都不再发送ICMPICMPICMP数据报
  3. 多播IPIPIP数据报都不发送ICMPICMPICMP数据报
  4. 对具有(应该包括源地址和目标地址)的特殊IPIPIP地址的数据报都不再发送ICMPICMPICMP数据报。

1.4.2 询问报文#

主要有:

  1. 回送请求和回答报文: 由主机或路由器询问另一台特定目的主机，需要由该目的主机回答自己的有关状态。用这种方式来获得目的主机的是否可达和有关状态。
  2. 时间戳请求和回答报文: 请某台特定目的主机回答自己的时间戳，在ICMPICMPICMP时间戳回答报文里有一个323232位的字段，表示从1900.01.011900.01.011900.01.01到当前经过的秒数。用这种方式进行时钟同步和时钟测量。

1.4.3 ICMPICMPICMP的应用#

1.4.3.1 ping命令#

ping命令是一个应用ICMPICMPICMP回送请求和回答报文的例子。

发起ping的主机一下子发送kkk个ICMPICMPICMP回送请求报文，而接受方响应这个请求报文并且回答报文。

由于往返的ICMPICMPICMP报文都带了时间戳，因此也很容易得出往返时间。

TTL=kTTL=kTTL=k的报文在发送给最后一个路由器RkR_kRk​后，TTLTTLTTL变为0，因此由RkR_kRk​发送ICMPICMPICMP超时报文给发送主机。

TTL=k+1TTL=k+1TTL=k+1的报文在发送给最后路由器RkR_kRk​后，TTLTTLTTL变为1，该报文是可以转发到目的主机上的！但是因为源UDPUDPUDP报文是不可交付的，目的主机收到报文后，会发送一个ICMPICMPICMP目的不可达差错报告报文。

有这个过程，就得到了发送方到目的主机上的所有路由器和最后的目的主机的ipipip。

1.5 路由选择协议: 路由器中的路由表从何而来#

希望有一个理想的路由选择算法，它:

  1. 必须是正确且完整的
  2. 计算简单
  3. 能够适应网络状况和网络拓扑的变化
  4. 算法应该稳定
  5. 算法公平
  6. 算法在某一种角度下是”最佳”的

路由选择分为静态路由选择策略(人工设置)和动态路由选择策略(自适应路由选择)。

一般路由选择总会分层次，把一个大网络分为较小的自治系统ASASAS(Autonomous System)。

自治系统ASASAS(Autonomous System)指的是在单一技术管理下的一组路由器。

让一个自治系统ASASAS对同层次的ASASAS都表现为一个单一的、一致的路由选择策略。原因在于:

  1. 网络规模比较大，如果每个路由表中存放了这个大网络的所有网路，那路由表会很大，浪费时间和效率
  2. 某些子网络部分并不希望其他部分知道内部网络的状况，但也希望能连接到互联网上。

在分层次的网络上进行路由选择就有2种形式:

  1. 内部网关协议IGPIGPIGP(Interior Gateway Protocol): 在域内进行路由选择 RIP、OSPFRIP、OSPFRIP、OSPF
  2. 外部网关协议EGPEGPEGP(External Gateway Protocol): 在域间进行路由选择 BGPBGPBGP[注意: 每一个ASASAS中至少有一个或多个路由器要运行EGPEGPEGP协议和其他ASASAS交换路由]

比如在AS24,AS777,AS46AS 24, AS 777 ,AS 46AS24,AS777,AS46内部进行路由选择就是域内路由选择。

而与其他ASASAS相连接的路由器则需要进行域间路由选择。

如果一级划分的ASASAS仍旧很大，达不到需求，可以进行二级甚至是多级划分。

1.5.1 内部网关协议IGPIGPIGP#

1.5.1.1 路由信息协议RIP(Routing Information Protocol)RIP(Routing \ Information \ Protocol)RIP(Routing Information Protocol)#

RIPRIPRIP是一种分布式的基于距离向量的路由选择协议。但是很少被使用。它最大的特点是简单，开销很小。

RIPRIPRIP协议定义距离:

  1. 从一路由器到直接连接的网络的距离定义为1。
  2. 从一路由器到非直接相连接的网络的距离定义为经过的路由器数+1。
  3. 定义距离为16及以上就为不可达。

RIPRIPRIP​要求路由器不仅记录网络号和下一跳地址，还要为每一表项记录到该网络的距离。

那么RIPRIPRIP的路由表大致长这样:

网络号[注意：网络号往往携带子网掩码信息]到该网络的距离下一跳地址
net−idnet-idnet−iddistancedistancedistancexx.xx.xx.xxxx.xx.xx.xxxx.xx.xx.xx

如此一来，RIPRIPRIP协议就能够选择一条经过最少路由器的一条路径。

1.5.1.1.1 RIPRIPRIP如何交换信息#

交换信息的要点是：

  1. 和谁交换=>=>=> RIPRIPRIP协议要求每个路由器仅和直接相邻的路由器交换信息。
  2. 交换什么样的信息=>=>=> 整一个路由表中所有的信息，就是”我到本自治系统中所有网络的(最短)距离，下一跳的地址”。
  3. 什么时候交换 =>=>=> 按照固定的时间间隔交换信息，比如间隔303030秒，保证路由中的信息是最新的。
1.5.1.1.2 RIPRIPRIP交换信息算法#

得到相邻路由器R′R'R′发送的路由信息

  1. ⋆\star⋆先进行”初始化”：把距离都+1，把下一跳地址都改为R′R'R′。

  2. 接着对**每一个表项row′row'row′**都执行以下过程:

    • 查看该表项对应的网络号是否存在于当前路由表，如果不存在，就把row′row'row′直接加入到路由表中。否则执行下一步

    • 该网络号已在路由表中，则查看该表项对应的下一跳地址X′X'X′，如果X′X'X′就是路由表中的下一跳地址，则直接更新路由表中的表项为row′row'row′[确保路由表中的信息总是最新的]。否则执行下一步

    • 该网络号在路由表中且下一跳地址并不相同，则查看该表项的距离distance′distance'distance′，如果distance′<distancedistance' < distancedistance′<distance才更新[确保路由表中的距离总是最近的]，否则就什么也不做，扫描下一个表项。

  3. ⋆\star⋆如果某个时间间隔里(3分钟)总接受不到某个相邻路由表的更新报文，就在路由表中把该路由器的表项都设置为不可达(距离为16)。

但是这样的算法会带来一定的问题，比如RIPRIPRIP中最大的问题**“好消息传得快，坏消息传得慢”**。

当一个网络出现故障时，RIPRIPRIP​协议往往要经过比较长的时间才能把这个信息传递给所有的路由器。

但是如果有一个路由器发现了一个更加短的路由，这种信息就传播的很快。

可以考虑以下事件：

坏消息传的慢事件：10.4.0.010.4.0.010.4.0.0到路由器CCC的网络不可达从可达变成不可达，CCC更新自己的路由表，把到10.4.0.010.4.0.010.4.0.0的表项的距离改为不可达。且在路由器CCC把更新的路由表传给BBB前，路由器BBB先把路由表传递给了CCC。

1.5.1.1.3 RIPRIPRIP协议报文格式#

RIP2RIP2RIP2协议支持子网划分和CIDRCIDRCIDR无分类编址网络。

RIP2RIP2RIP2协议数据报使用UDPUDPUDP协议进行传输！因此应该是RIP2RIP2RIP2数据报文封装在UDPUDPUDP数据报中再封装IPIPIP数据报里传输。

RIPRIPRIP自身的数据报文由首部和路由部分组成。

特别地，由于一个路由部分最多可以放入252525个路由信息，因此一个RIPRIPRIP数据报的最大长度是25∗20+4=50425*20+4=50425∗20+4=504字节。

RIPRIPRIP协议还可以进行简单地鉴别功能，使用鉴别功能时将第一个路由信息作为鉴别信息。把地址族标识改为000xFFFFFFFFFFFF(全1)，而路由标记写入鉴别类型，剩余的16个字节全都可以作为鉴别数据。

1.5.1.2 开放最短路径优先协议OSPFOSPFOSPF(Open Shortest Path First)#

OSPFOSPFOSPF最大的特征是使用了分布式的链路状态协议。它就是为了克服RIPRIPRIP​​协议的缺点而开发的。

OSPFOSPFOSPF协议的目的是让每一台路由器都能够维护一个链路状态数据库，也就是全网的带权拓扑图。在这张带权图上跑dijkstradijkstradijkstra​​就能找到该路由器到其他路由器的最短路径。

链路状态数据库的同步是指使得不同路由器的链路状态数据库变得一样。

完全邻接指的是相邻的 同步路由器。

OSPFOSPFOSPF的另一特征是更新收敛的速度非常快。(RIPRIPRIP比较慢)。

1.5.1.2.1 OSPFOSPFOSPF如何交换信息#

交换信息的要点有3条:

  1. 和谁交换信息 =>=>=> OSPFOSPFOSPF协议要求每台路由器和自治系统内的所有路由器都发送信息。使用的方法是泛洪法。
  2. 交换哪些信息 =>=>=> OSPFOSPFOSPF协议要求路由器分享和本路由器相邻的所有路由器的链路状态(路由器知道的部分信息)。其中链路状态包括相邻路由器的地址和连接到该路由器的度量(可以被称为是代价)。
  3. 何时交换信息 =>=>=> OSPFOSPFOSPF中无需路由器定时发送自己的链路状态信息。只需要链路状态发生改变时发送链路状态信息即可。

由于每台路由器都要和自治系统内部所有路由器都发送信息，想必网络拥塞程度会非常大，为了能让OSPFOSPFOSPF可以在大网络上运行，往往会把一个自治系统划分为几个区域(用32位bitbitbit标识)。并且把泛洪法交换信息的范围从整个AS变为整个区域。

把区域分为2大类:

  1. 主干区域(backbone Area): 标识符为0.0.0.00.0.0.00.0.0.0，联通其他区域
  2. 其他区域

并且划分出3类特殊的路由器:

  1. 区域边界路由器(area border router): 处于每个区域和主干区域交接处的路由器。其他区域来的信息都由区域边界路由器进行概括。
  2. 主干路由器(backbone router): 处于主干区域的路由器。
  3. 自治系统边界路由器：处于主干区域中，专门处理本自治系统和其他自治系统之间的路由交换。

层次划分又一次使得网路变得容易在大规模的情况下变得适用。

1.5.1.2.2 OSPFOSPFOSPF协议报文格式#

OSPFOSPFOSPF协议不再使用UDPUDPUDP协议传输报文，而是直接使用IPIPIP协议传输报文。

OSPFOSPFOSPF5种分组是:

类型描述
问候(Hello)分组用以发现和维持相邻站点的可达性

OSPFOSPFOSPF规定每101010秒钟都要交换一次问候分组，以此知晓哪些邻站可达。如果间隔404040秒钟没有收到某个相邻路由器的问候分组，则认为该路由器不可达。

OSPFOSPFOSPF协议一般并不采用泛洪法来从空白链路状态数据库建立完整的链路状态数据库，只有在链路状态发生改变的时候才进行泛洪法。

而建立的方法一般是：

  1. 路由器和邻站交换状态数据库的摘要[哪些链路已经被写入数据库]
  2. 向邻站请求缺少的链路状态

以此大大减少了网络的负担。

而当有路由器的邻接链路状态发生改变时，采用可靠的泛洪法(泛洪法+确认信息)来向整个区域内的路由器都通知这个消息。

OSPFOSPFOSPF​协议还有以下几个特点:

  1. OSPFOSPFOSPF协议允许管理员给一条链路设置不同的度量以适应不同的业务。(比RIPRIPRIP灵活)
  2. OSPFOSPFOSPF允许负载均衡的情况，即当多条路径的总度量都一样时，可以允许把起点到终点的数据报分散到这几条路径中去。(RIPRIPRIP只会选其中一条，比RIPRIPRIP高效）
  3. 所有在OSPFOSPFOSPF中的链路之间都可以进行鉴别，可以仅在信任的路由器之间同步链路状态
  4. 也可以支持子网划分和CIDRCIDRCIDR无分类编址方式。
  5. OSPFOSPFOSPF让每一段链路都带上一个**32bit32bit32bit​的序号**，序号越大，链路状态越新。
  6. 每隔303030秒，刷新一次链路状态数据库。
  7. 为了更多地减少路由器之间的信息交换，OSPFOSPFOSPF又选定某些特殊路由器作为指定路由器(其他所有的路由器的信息都传递给他，由它转交给其他路由器)，从两两之间的N(N−1)N(N-1)N(N−1)减小到2∗N2*N2∗N。
